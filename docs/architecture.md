# Architecture

Three parts:

1. **The site.** Astro builds static HTML from the case files. It ships no client-side JavaScript.
2. **The Worker.** It runs first on every request. It redirects the other hostnames ([D-015](decisions.md)), answers the form routes (suggest a case, subscribe, confirm, unsubscribe) and hands everything else to the built site. It stores what the forms send in a private D1 database and sends the confirmation email through cfmail. A daily job deletes what has passed its time.
3. **The desk.** A weekly run of AI agents on Jan's Mac. It finds leads, writes and checks cases, reviews old ones, and publishes what passes ([D-009](decisions.md)).

Personal data (suggestions, subscriber addresses) lives only in D1. Leads, which are unconfirmed claims about named companies, also live only in D1. The public repository holds published cases only.

## What may depend on what

```
pages → layouts → components → lib → data
pages → og → lib
worker → lib → data
desk → lib → data
scripts → lib, data
```

- `lib/` is pure. It takes data and dates as arguments and returns values. It never reads files, the clock or the network. A lint rule holds this ([engineering.md](engineering.md#rules-and-their-guards)).
- The edges supply I/O. Astro reads the case files. The Worker reads requests and D1. The desk reads feeds, archives, D1 and the repository. Each passes today's date in.
- A rule two parts both apply has one home in `lib/`. The site and the desk both ask "which cases are due for review?" and both call `lib/review.ts`. The Worker validates a suggestion with `lib/suggestion.ts`, and the suggestion form's `maxlength` attributes read the same limits.
- Worker handlers in `src/worker/` do the I/O. Each takes the request, its bindings and a `Deps` value holding the date, the random bytes and a `sendMail` function, so a test passes fixed ones. Production passes the clock, the runtime's random bytes and the cfmail sender; the only code that reads the clock is `src/worker/index.ts`.

Form routes, answered by the Worker. A route that takes a form answers with a 303 to one of the pages above, so a reload never sends the form twice.

| Route | Does |
|---|---|
| `POST /api/suggest` | Stores a suggestion or an error report and redirects to `/suggest/thanks`; anything invalid, or over the rate limit, goes to `/suggest/problem` |
| `POST /api/subscribe` | Stores an unconfirmed address with a token and emails the confirmation link; redirects to `/subscribe/check-email`. A known address gets the same page and no email |
| `GET /confirm?token=` | Confirms the address and redirects to `/subscribe/confirmed`; an unknown or expired token goes to `/subscribe/problem` |
| `GET /unsubscribe?token=` | Serves the one-button page at this address and changes nothing |
| `POST /unsubscribe` | Deletes the address and redirects to `/subscribe/unsubscribed`. A mail program's one-click POST ([RFC 8058](https://www.rfc-editor.org/rfc/rfc8058)) gets a 200 |

A form with the hidden field `website` filled in is a bot: it gets the normal thank-you page, and nothing is stored or counted. The suggest and subscribe routes each allow 5 attempts per visitor per hour ([D-016](decisions.md)).

The unsubscribe step needs no script. Static pages cannot read their own query string without JavaScript, so the Worker serves the built page `/subscribe/unsubscribe/` at `/unsubscribe?token=...`. The page's form has no `action`, so the browser posts it back to the address it came from, token included.

The share cards have no browser behind them. `src/og/render.ts` reads the `.woff` files of Prata and Inter (satori reads WOFF, TTF and OTF, not WOFF2), hands the layout from `lib/share.ts` to satori, which draws it as SVG, and resvg turns that into a PNG ([D-017](decisions.md)).

## Outside the site

| Service | What it does | Data it holds |
|---|---|---|
| Cloudflare | DNS, redirects, the Worker, D1, cookieless analytics | Suggestions and subscriber addresses, in D1 |
| cfmail | Sends the confirmation email and the desk's weekly report, through a service mailbox ([D-008](decisions.md)) | Copies of mail it sent |
| Claude Code | Runs the desk's agents on Jan's subscription | Nothing kept |
| Wayback Machine | Archived copies of sources | Public pages only |
| GitHub | Code and the public history of every case ([D-004](decisions.md)) | Published cases |
